# Развёртывание на Railway

Приложение загружается из локальной папки через Railway CLI. Доступ Railway к GitHub-репозиторию организаторов не требуется. Сборка использует корневой `Dockerfile`.

- Публичный адрес: https://sobrano-production.up.railway.app
- Проект: `enthusiastic-grace` (`b92e2ecd-42f5-45b6-9a79-fede49aef8ab`).
- Сервис: `sobrano`, окружение: `production`.
- Панель: https://railway.com/project/b92e2ecd-42f5-45b6-9a79-fede49aef8ab

## Настройки

В Variables сервиса заданы `OPENAI_API_KEY`, `OPENAI_MODEL` и `OPENAI_EMBEDDING_MODEL` из локальной конфигурации. Ключ хранится только в серверных переменных Railway. `.railwayignore` исключает локальные секреты, кеши и настройки инструментов из загружаемого архива.

Дополнительные переменные:

```dotenv
PORT=3000
CACHE_DIR=/app/.cache/sobrano
RAILWAY_RUN_UID=0
```

К сервису подключён постоянный том `sobrano-volume` по пути `/app/.cache/sobrano`. Он сохраняет эмбеддинги и результаты между деплоями. Railway монтирует том от root; `RAILWAY_RUN_UID=0` позволяет текущему образу записывать в него. Это настройка удалённого окружения; локальный Docker Compose продолжает запускать приложение от пользователя `node`.

Используется один экземпляр приложения. Для нескольких экземпляров потребуется согласованное внешнее хранилище кеша. Данные каталога включены в Docker-образ. Для сборки нужны npm и Docker Hub, для новых AI-запросов — доступ к OpenAI и доступный баланс API. Хостинг и том расходуют ресурсы аккаунта Railway; приложение предназначено для демонстрации и пока не ограничивает расход API на публичные запросы.

## Повторный деплой

Сначала проверьте, что CLI авторизован в нужном аккаунте:

```bash
railway whoami
railway link --project b92e2ecd-42f5-45b6-9a79-fede49aef8ab --environment production --service sobrano
railway up --detach
railway deployment list --json
railway logs --build --lines 50
railway logs --lines 50
```

`railway up` загружает текущее содержимое папки, включая незакоммиченные изменения. Автоматического деплоя при push в GitHub нет. Переменные и том при повторной загрузке сохраняются.

## Проверка

```bash
curl --fail https://sobrano-production.up.railway.app/api/health
```

Ожидается `{"status":"ok","profiles":66}`. Затем откройте сайт в приватном окне и нажмите «Найти совпадения». Должны появиться три карточки. Проверьте также примеры другой даты, флористов, малого бюджета и отсутствующей категории. Health проверяет каталог; реальный AI проверяется запросом подбора. При недоступности AI интерфейс явно показывает резервный режим.

Проверьте ссылку с телефона через мобильную сеть перед защитой. Для остановки публичного экземпляра после оценки можно удалить активный деплой через панель Railway; том следует сохранить, если нужен кеш. Не удаляйте проект или том без намерения потерять сохранённые результаты.

## Состояние

Проверено 23 сентября 2026 года. Деплой `c047d86c-d9a7-4892-8de7-6d3175b7a971` завершился со статусом `SUCCESS`. Docker-сборка и проверка TypeScript прошли на Railway.

- Шесть API-сценариев прошли, повтор каждого вернул идентичный результат. Все четыре сценария с карточками использовали смысловой подбор и AI-объяснения (`semantic` / `ai`). Начальные запросы с AI заняли 2,1–4,7 секунды в одном прогоне; это не гарантия задержки. [Ответы API](evidence/railway-smoke.json).
- Пять Playwright-проверок прошли в новых браузерных контекстах без авторизации: экраны 414 и 1024 px, все демонстрационные исходы, некорректный ввод и повтор после имитации сетевого сбоя. Команда: `APP_URL=https://sobrano-production.up.railway.app npx playwright test tests/browser/finder.spec.ts --grep '414px|1024px|all demo outcomes|invalid API input|network error'`.
- После перезапуска сервиса 24 ответа совпали с сохранёнными до перезапуска. Health вернул 66 профилей. [Проверка после перезапуска](evidence/railway-runtime.json).

Проверку с отдельного физического устройства и мобильной сети нужно выполнить команде. Доступность API подтверждена реальными запросами, но остаток баланса и лимиты аккаунтов Railway/OpenAI не проверялись. Перед защитой проверьте их в панелях провайдеров.
