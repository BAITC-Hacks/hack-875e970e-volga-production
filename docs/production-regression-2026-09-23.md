# Регресс production — 23 сентября 2026

Проверен https://sobrano-production.up.railway.app без авторизации. Основной сценарий работает; регресс **не полностью зелёный**: подтверждены проблема конкретности AI-объяснения, технические сообщения при сбоях и переполнение при увеличении текста. Критических нарушений фильтрации в проверенной выборке не обнаружено.

## Найденные проблемы

### F-01 — Medium: общая реклама вместо индивидуального основания

**Требование:** R2b/D2, конкретность и невзаимозаменяемость объяснений; главный риск для качества результата и убедительности демо.

Выполнить `POST /api/recommendations`:

```json
{"city":"Алматы","date":"2026-10-15","format":"корпоратив","category":"Лайв-бэнд","budget":2000000,"wishes":""}
```

Фактически: `HK-25279`, `explanationMode=ai`, `warnings=[]`. Основание: «И да, мы действительно сверкаем — звуком, энергией и атмосферой, которую создаём на сцене.» Оно может описывать любой музыкальный коллектив. Первое предложение о дате/цене/формате достоверно, но не исправляет отсутствие индивидуального преимущества.

Ожидается конкретный факт из анкеты либо честное сообщение о недостатке сведений. В исходном описании этого профиля конкретной особенности нет; выдумывать её нельзя. Строгую выдачу всех подходящих профилей ради красивого объяснения нарушать также нельзя.

Независимая попытка опровержения подтвердила дефект. `lib/ai.ts:71–78,99–108` проверяет число слов, небольшой blacklist и лексические повторы, но не смысловую конкретность. Предыдущее исправление одинаковых объяснений работает; это другой, оставшийся пробел.

### F-02 — Low: пользователю показывается техническая ошибка

Открыть production, в браузерном перехвате прервать `/api/recommendations` или вернуть HTTP 503 с HTML/plaintext, нажать «Найти совпадения».

Фактически: `Failed to fetch` либо `Unexpected token ... is not valid JSON` в Chromium; в других движках собственные технические сообщения. Ожидается понятное сообщение на русском с предложением повторить. Причина: `app/finder.tsx:38–43` разбирает JSON до обработки статуса и выводит `Error.message` напрямую.

Повтор после снятия перехвата проходит, форма сохраняется. Это клиентская симуляция на настоящем production UI; сервер намеренно не отключался.

### F-03 — Medium для доступности: горизонтальное переполнение при увеличении текста

Открыть production при viewport 320 px, выполнить подбор, задать `document.documentElement.style.fontSize='200%'`.

Фактически: ширина документа 640 px в Chromium/WebKit, 639 px в Firefox при доступных 320 px. [Скриншот Chromium](evidence/regression-2026-09-23/chromium-large-text.png). Появляется горизонтальная прокрутка. Ожидается читаемый интерфейс в доступной ширине.

Это имитация увеличенного базового шрифта, а не проверка всех настроек системного масштабирования и не заявление о полной WCAG-сертификации. При обычном шрифте отдельный замер Chromium на 320 px также дал 321 px — малое переполнение, Low. Основные размеры от 375 px в существующем наборе проходят.

## Исследовательское и интуитивное тестирование

После основного регресса проверены гипотезы, возникающие при обычной работе пользователя:

- **«Изменил бюджет — эти карточки уже новые?»** После изменения 1000000 на 100000 старые три карточки остаются. Сводка честно показывает прежний бюджет; после отправки получаем пустой результат. Это UX-риск смешения черновика и выполненного запроса, а не подтверждённое нарушение фильтра. Полезно помечать «Условия изменены, выполните подбор заново».
- **«Удалил обязательное значение и передумал».** Пустой бюджет не отправляет запрос; исправление работает.
- **«Сеть пропала, затем появилась».** Восстановление проходит. Текст ошибки — F-02.
- **«Нажал во время загрузки».** Поле бюджета и кнопка отключены, aria-busy выставлен; один запрос. Задержка добавлена только в клиентский перехват, ответ остаётся реальным.
- **«Ввёл инструкцию обойти фильтры и HTML».** В пожеланиях попросили вернуть занятых бесплатно, выдумать отзывы и добавили `<script>`. Ограничения не обойдены, цитаты подтверждены CSV, HTML отображается текстом, маркер JavaScript не выполняется. Один пробный payload не является полным pentest или доказательством абсолютной устойчивости к prompt injection.
- **«Работаю клавиатурой».** Основные поля достижимы Tab, календарь закрывается Escape. Первичная проверка WebKit после открытия мышью не возвращала focus; контрольное открытие клавишей Enter после фокуса возвращает его корректно. [Контроль](evidence/regression-2026-09-23/webkit-keyboard.json). Подтверждённым клавиатурным дефектом это не считаем.
- **«Пришёл по HTTP / вижу старую иконку».** HTTP перенаправляет на HTTPS (301), действительная SVG-иконка отдаётся 200 и совпадает с новой локальной. `/favicon.ico` — 404, но он не подключён и дефектом не является.

Дополнительно: `/data/hackathon_dataset_anonymized.csv`, `/.env`, `/.git/config` возвращают 404; необработанных pageerror в трёх браузерах не замечено; `lang=ru`, один h1, у проверенных полей есть labels. Контраст, screen reader и полная доступность не сертифицированы.

## Границы и приоритеты

Не выполнены: разрушительная нагрузка, исчерпание API-лимита, выключение OpenAI на сервере, удаление production-кеша, новый restart/deploy, проверка дискового отказа, физический телефон/мобильная сеть, исчерпывающий аудит безопасности, баланс провайдеров и clean-start Compose. Прямого подтверждения фактического обращения к OpenAI через серверные логи нет: новый текст вернул semantic/ai, но endpoint не показывает cache-hit; AI-режим не следует трактовать как доказательство отсутствия кеша.

По критериям: работающий сценарий и качество фильтров подтверждены; качество индивидуальных объяснений ослабляет F-01. Пользовательская ценность, инновационность и масштабирование требуют аргументов и исследования, регресс их не измеряет. Для демо приоритет — F-01, затем F-02; F-03 важен для доступности. В документации остались исторические противоречия: hackathon-plan утверждает отсутствие публичного адреса, старый spec-report содержит первоначальное состояние до исправлений. Этот отчёт фиксирует текущий production-прогон, не переписывая историю.
