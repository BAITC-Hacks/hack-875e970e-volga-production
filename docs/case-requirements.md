# Требования кейса #79-lite

Источник: [официальное ТЗ, вкладка RU](https://docs.google.com/document/d/1rhR2HFY164BrnkIP39N3usY9fNY4JeAgkPxEzbqL00w/edit?tab=t.9tqw3yk75922). Проверено 23.09.2026 через текстовый экспорт Google Docs. Ниже краткая нормализованная сводка, не дословная копия. При разночтениях первоисточник приоритетнее сводки.

| ID | Требование |
| --- | --- |
| R1 | Вход: город, дата, формат, категория, бюджет; язык и длительность необязательны |
| R2a | Максимум три карточки: имя, категория, город, цена |
| R2b | Объяснение в 1–2 предложения с основаниями соответствия; общая реклама недопустима |
| R3 | Исключать занятых; площадки обрабатывать так же |
| R4 | При нехватке показывать всех подходящих, объяснять количество |
| R5 | Одинаковый запрос сохраняет порядок |
| R6 | Явно различать успех, отсутствие категории в городе и несовпадение условий |
| D1 | Ориентир задержки — 10 секунд |
| D2 | Объяснения различимы даже без имён |
| D3 | Повторный запуск сохраняет порядок |
| D4 | Изменение даты меняет выдачу; причина занятости видна пользователю |
| D5 | Демонстрировать плотную осеннюю категорию, редкую и пустую выдачу |
| D6 | Объяснять пустоту словами |
| D7 | Команда объясняет пайплайн |
| E1/E2 | Вне объёма: бронирование, заявки, уведомления, дообучение |

Приоритет: объяснения → корректность редких/занятых/пустых случаев → скорость → интерфейс. Красота UI не обязательна.

Баллы: работоспособность 25, техническая реализация 25, README/воспроизводимость 25, ценность 15, развитие/оригинальность 10. Эта таблица отличается от общей таблицы `AGENTS.md`; для кейса используем официальную. Правила команды о Compose и документации сохраняются.
