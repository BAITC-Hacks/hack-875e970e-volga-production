# Контекст AI-чата для подбора ведущего

Обновлено: 23 сентября 2026. Проект: «Собрано», кейс «Умный подбор подрядчиков (#79-lite)» для команды Volga Production. Рабочая директория — корень этого репозитория. Официальное ТЗ — [Google Doc, вкладка RU](https://docs.google.com/document/d/1rhR2HFY164BrnkIP39N3usY9fNY4JeAgkPxEzbqL00w/edit?tab=t.9tqw3yk75922). Правила работы — в `AGENTS.md`; согласованные решения по кейсу — в `docs/hackathon-plan.md`; инструкция запуска, проверка пунктов ТЗ и ограничения продукта — в `README.md`.

## Что уже работает

- Обновление страницы в той же вкладке сохраняет форму, карточки (включая пустую выдачу), вступительный ответ, переписку и черновик вопроса через `sessionStorage`. Завершённые запросы не повторяются; незавершённое вступительное сравнение запускается заново, вопрос без полученного ответа остаётся черновиком. Изменение условий очищает сохранённый результат и диалог. Сохранение ограничено сессией вкладки и доступностью браузерного хранилища; это не серверная история. Реализация: `lib/finder-session.ts`, `app/finder.tsx`.
- Форма задаёт город, дату, формат, категорию, бюджет, необязательные язык, длительность и текст «Что для вас важно?». Сервер проверяет значения по каталогу из 66 анонимизированных профилей.
- Строгие фильтры исключают занятых на дату и не подходящих по городу, категории, формату, бюджету, языку или длительности. Затем смысловая близость анкет ранжирует прошедших кандидатов. Показывается не более трёх карточек с источниками и причинами выбора.
- Для категории «Ведущий» сначала появляются до трёх карточек, затем отдельно загружается связный AI-ответ и чат для уточнений. Первая карточка выделена как «первый по близости к запросу»; при сбое смыслового ранжирования — как «первый по начальной цене». Это приоритет в порядке выдачи, не оценка качества подрядчика. Остальные карточки остаются видимыми и сравнимыми. Для остальных категорий сохраняется обычный подбор без продолжения диалога. Изменение формы сбрасывает чат; ошибка отправки уточнения сохраняет текст вопроса.
- Ответ чата строится только по кандидатам, заново отфильтрованным сервером. Текст вопроса не меняет условия формы. Поддельные ответы ассистента, присланные из браузера, игнорируются; для контекста используются не более трёх последних пользовательских реплик как недоверенные данные. Запросы на другую категорию, изменение фильтров и раскрытие служебных инструкций получают безопасную подсказку. При недоступности AI показывается явно обозначенный резервный ответ.
- Модель для выбора цитат и чата — `gpt-5.6-sol`; для связного ответа установлен `reasoning.effort=low` и серверный лимит 8,5 секунды. Эмбеддинги — `text-embedding-3-small`. Браузер ждёт карточки и каждый ответ чата не более 10 секунд. На ранжирование и выбор цитат действует общий серверный лимит 8 секунд. Локальный `.env` исключён из Git; образец без секретов — `.env.example`.
- Результаты и ответы кешируются по версии каталога, модели и нормализованному запросу для повторяемости. Это рассчитано на один экземпляр приложения с сохранённым кешем.

## Решения после сверки с ТЗ

- Пункт Definition of Done о времени ответа задаёт ориентир до 10 секунд. Прежний запрос `/api/recommendations` ожидал и карточки, и связный AI-текст; фактические ответы доходили до 11–13,5 секунды, а интерфейс сообщал о 30 секундах. Теперь `/api/recommendations` возвращает только результат подбора. Для вступительного сравнения ведущих интерфейс затем вызывает `/api/chat` с пустым `message`; обычный вопрос отправляется туда же с текстом.
- Карточки размещены перед связным ответом и чатом. При двух подходящих кандидатах сообщение над карточками объясняет, что показаны все прошедшие условия; причины исключения видны ниже. Для нулевого результата отдельно различаются отсутствие категории в городе и отсутствие проходящих ограничения кандидатов.
- Три карточки не обязаны выглядеть равнозначными: первая визуально выделена, но формулировка приоритета отражает действующий алгоритм. При недоступности AI объяснения и чат переходят в явно обозначенный резервный режим. Сведения из анкет, цена «от» и календарная доступность не выдаются за независимо проверенные факты.

## Подтверждённые проверки

- Сохранение после обновления: один адресный браузерный тест `tests/browser/persistence.spec.ts` (`--grep 'reload restores selection'`) прошёл на dev-сервере `http://localhost:3002` за 3,8 секунды. Проверены карточки, ответы, черновик, отсутствие повторных API-запросов, продолжение диалога и сброс при изменении условий. Использованы явно заданные фикстуры API; качество AI этим тестом не проверялось. Проверка типов прошла. Два дополнительных теста в файле не запускались успешно: по просьбе команды проверка ограничена основным сценарием. Работающий Docker-контейнер на порту 3000 после этого изменения не пересобирался.
- `npm test`: 19 тестов прошли. `npm run typecheck` и `npm run build`: прошли.
- 12 браузерных тестов Docker-версии прошли: ширины 375, 414, 768, 1024 и 1440 px, три карточки с выделенным первым вариантом, показ карточек до завершения AI-сравнения, смена даты, редкая и пустые выдачи, источники, чат, сброс диалога и повтор после сетевой ошибки. После финальной пересборки отдельный тест появления карточек прошёл по `http://127.0.0.1:3000`.
- Шесть реальных сценариев API записаны в `docs/evidence/smoke.json`. 24 параллельных повторных ответа совпали с ними; результат в `docs/evidence/runtime.json`.
- Субагент на Astra выполнил 13 живых HTTP-проверок: сложные предпочтения, уточнения, prompt injection, занятый кандидат, попытка сменить категорию и условия, выдуманные рейтинг и услуги, бронирование, поддельная история, невалидный ввод, пустая выдача и отсутствие ключа. Блокирующих проблем в этих проверках не найдено. Это не доказывает абсолютную защиту от любых инъекций или ошибок модели.
- Чистый запуск обновлённой версии выполнен в отдельном Compose проекте `sobrano_verification` с новым томом: контейнер `healthy`, реальный подбор и чат прошли. Хостовый Node-процесс также занимал порт 3000 на IPv4, поэтому замеры контейнера выполнены по IPv6 `http://[::1]:3000`. Позже старый dev-сервер этого репозитория остановлен, финальная версия пересобрана и проверена по обычному `http://127.0.0.1:3000`. Карточки в шести сценариях пришли за 0,005–5,662 секунды; один из трёх AI-ответов честно перешёл в резервный режим за 8,517 секунды. 24 повторных ответа совпали с зафиксированными. Контейнер оставлен работающим на порту 3000.
- Измерения относятся к этому локальному прогону и не гарантируют ту же скорость при другой сети или загрузке. Первые замеры через `localhost` случайно попали в старый IPv4 dev-сервер и были заменены повторным прогоном по явному адресу контейнера.

Для продолжения локальной проверки используйте `docker compose -p sobrano_verification ps`, адрес `http://127.0.0.1:3000` и `APP_URL=http://127.0.0.1:3000 node --import tsx scripts/verify-runtime.ts`. Тестовый экземпляр можно остановить командой `docker compose -p sobrano_verification down`; том с кешем при этом сохраняется. Если запускать обычный `docker compose up`, сначала освободите порт 3000, остановив этот тестовый экземпляр.

## Что важно сделать дальше

1. Перевыпустить OpenAI API-ключ: во время диагностики его строка из локального `.env` случайно попала в вывод инструмента. Ключ не добавлен в Git; его значение не записывать в документацию или логи.
2. Перед защитой перепроверить чистый запуск и основной сценарий на машине команды после перевыпуска ключа; проверить, что ключ задан только в серверном окружении.
3. Перед демонстрацией ещё раз оценить качество свободного AI-ответа на реалистичных предпочтениях. Карточки имеют проверяемые цитаты, но связный ответ — интерпретация анкет и может ошибаться. Заявления подрядчиков не являются независимой проверкой; цена указана «от», календарь не подтверждает бронь.
