# Собрано — умный подбор event-подрядчиков

Прототип команды **Volga Production** для кейса «Умный подбор подрядчиков (#79-lite)». Заказчик задаёт условия мероприятия и получает **до трёх карточек с проверяемыми объяснениями** из предоставленного каталога Казахстана.

Не бронирует и не отправляет заявки. Пустая выдача — отдельный объяснённый результат, а не ошибка.

**Решение команды:** README — единственный материал для предпрезентации. Отдельные презентации, слайды, сценарии защиты и видеозаписи не готовим. Основной объём работы — приложение, его проверка и воспроизводимое описание здесь.

## Быстрый запуск через Docker Compose

### Требования

- Docker Desktop / Docker Engine с Docker Compose v2+; Docker daemon запущен.
- Свободный порт `3000`.
- Доступ к интернету: при сборке — Docker Hub и npm; при новых AI-запросах — `api.openai.com`.
- OpenAI API-ключ с балансом и доступом к `gpt-4.1-mini` и `text-embedding-3-small`.
- Исходный файл `hackathon dataset anonymized .csv` в корне репозитория. Он уже включён; 66 профилей, отдельная БД не нужна.

1. Из корня проекта создайте конфигурацию, **если `.env` ещё нет**:

   ```sh
   cp .env.example .env
   ```

2. Вставьте свой ключ в `OPENAI_API_KEY` внутри `.env`. Не коммитьте его. Пример:

   ```dotenv
   OPENAI_API_KEY=ваш_ключ
   OPENAI_MODEL=gpt-4.1-mini
   OPENAI_EMBEDDING_MODEL=text-embedding-3-small
   ```

3. Соберите и запустите:

   ```sh
   docker compose up --build -d
   docker compose ps
   curl http://localhost:3000/api/health
   ```

   Ожидаемый health-ответ: `{"status":"ok","profiles":66}`. Откройте **http://localhost:3000**. Health проверяет каталог, а не доступность OpenAI.

4. Нажмите **«Найти совпадения»** с исходными параметрами формы. При первом AI-запросе эмбеддинги 66 анкет создаются автоматически и сохраняются в Docker-томе `selection-cache`. Если API недоступен или не уложился в срок, появится явно обозначенный резервный режим. Пройдите примеры под формой.

5. Остановка и повторный запуск:

   ```sh
   docker compose down
   docker compose up -d
   ```

   Кеш сохраняется после остановки. `docker compose down -v` удаляет **только тома этого Compose-проекта**, включая сохранённые результаты; после этого AI-запросы оплачиваются заново. Используйте эту команду только для намеренного сброса/проверки чистого запуска.

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `OPENAI_API_KEY` | Серверный ключ OpenAI; без него работает явно обозначенный резервный подбор |
| `OPENAI_MODEL` | Модель выбора цитат, по умолчанию `gpt-4.1-mini` |
| `OPENAI_EMBEDDING_MODEL` | Модель смыслового поиска, по умолчанию `text-embedding-3-small` |
| `CACHE_DIR` | Локально `.cache/sobrano`; Compose задаёт `/app/.cache/sobrano` |

Ключ не попадает в клиентский JavaScript, образ Docker или ответы API. `.env` исключён из Git и Docker-контекста. В OpenAI передаются описания анонимизированных анкет и параметры запроса; не вводите персональные данные в пожелания. Для Responses используется `store: false`. Локальный кеш содержит параметры запросов и результаты, без ключей.

## Разработка без Docker

Node.js 22+, npm; зависимости закреплены `package-lock.json`.

```sh
npm ci
# Подготовьте .env по инструкции выше.
npm run prepare:data
npm run dev
```

Откройте http://localhost:3000. `prepare:data` проверяет каталог и создаёт эмбеддинги заранее; это опционально. Для production: `npm run build`, затем `npm start`.

| Команда | Что проверяет / делает |
| --- | --- |
| `npm test` | Фильтры, данные, валидация, смысловое ранжирование, сбои, подтверждение цитат и кеш |
| `npm run typecheck` | Типы TypeScript |
| `npm run build` | Production-сборка Next.js |
| `npx playwright install chromium` | Однократная установка тестового браузера |
| `npm run test:e2e` | Браузерные проверки; приложение должно работать на порту 3000 |
| `node --import tsx scripts/smoke.ts` | Реальные API-запросы, повторяемость; сохраняет результаты в `docs/evidence/smoke.json` |
| `node --import tsx scripts/verify-runtime.ts` | Сравнивает 24 параллельных ответа с сохранённым smoke-прогоном; запускать после него, в том числе после перезапуска контейнера |

`APP_URL` позволяет smoke-скрипту и Playwright проверять другой адрес. Тесты `npm test` используют явно заданные тестовые сервисы и не расходуют API. Smoke и браузерные сценарии обращаются к настоящему приложению; новые запросы могут расходовать API.

## Устройство решения

```text
Форма → серверная валидация → город + категория
                              ↓
          дата + цена + формат + язык + длительность
                              ↓
     эмбеддинги: смысловая близость формата и пожеланий
                              ↓
            сортировка → максимум 3 подрядчика
                              ↓
  AI выбирает цитату → код проверяет её в исходной анкете
                              ↓
       фактическое объяснение + источник + причины исключения
```

- `app/`: интерфейс, стили и HTTP-маршруты; `lib/`: каталог, фильтрация, OpenAI, кеш и подбор.
- `tests/`: автоматические проверки; `scripts/`: подготовка данных и реальные проверочные прогоны.
- `docs/`: принятые решения и результаты технической проверки; `public/`: статические ресурсы приложения.
- Next.js App Router + React + TypeScript; CSV разбирает `csv-parse`, вход и ответ модели проверяет Zod. Отдельной БД, векторного сервера и дообучения нет.

### Фильтрация и ранжирование

Город и категория проверяются по структурированным полям. Описание о выездах не отменяет фильтр города. Цена «от» должна быть не выше бюджета. Занятые на дату исключаются всегда. Если язык или часы заданы, они также обязательны. `max_hours = null` означает «присутствие не применимо»; не ноль и не неизвестную длительность. Список категорий разбирается как массив.

Семантический запрос содержит категорию, формат и пожелания; без пожеланий ищется опыт соответствующего формата. Косинусное сходство округляется до шести знаков, затем равенство разрешается по цене и `id`. Сходство не показываем как процент качества или вероятность успеха.

AI выбирает конкретную дословную цитату и тип особенности. Сервер проверяет идентификаторы и наличие цитаты в `description`, затем сам формирует текст с датой, форматом, бюджетом и выбранной особенностью. Свободные обещания модели в карточки не попадают. Под раскрываемым блоком доступен полный источник. Смысловая релевантность цитаты всё равно требует оценки человеком.

### Детерминизм и сбои

Кеш содержит версию алгоритма, хеш CSV, модели и нормализованные параметры. Он хранит эмбеддинги и полные ответы; одновременные одинаковые запросы внутри одного процесса объединяются. Запись атомарная. Один и тот же запрос при неизменной версии данных сохраняет порядок после перезапуска благодаря постоянному тому.

На внешние обращения выделено суммарно 8 секунд, автоматических повторов SDK нет. Если смысловой этап недоступен, остаются строгие фильтры и сортировка по цене/ID; если недоступен выбор цитаты, используется выдержка из анкеты. Резервный режим явно указан и **тоже кешируется**, чтобы повтор не менял порядок. Для его намеренного пересчёта нужно очистить соответствующий кеш; не делайте этого между проверками детерминизма.

Гарантия относится к одному экземпляру приложения с сохранённым кешем и неизменными данными/версиями. Для нескольких серверов понадобятся общий кеш и распределённая блокировка. Удаление кеша или изменение моделей/данных — новый расчёт.

## HTTP API

`POST /api/recommendations`, `Content-Type: application/json`:

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "format": "корпоратив",
  "category": "Ведущий",
  "budget": 1000000,
  "language": "английский",
  "hours": 5,
  "wishes": "Спокойная подача для делового вечера"
}
```

Обязательны первые пять полей. Возвращаются `status`, `cards` (0–3), `query`, `total`, `eligible`, `excluded`, `message`, `ranking`, `explanationMode`, `warnings`.

- `matched`: хотя бы один подходящий профиль.
- `category_absent`: в этом городе нет такой категории.
- `no_match`: категория есть, но никто не проходит все ограничения.

В `excluded` счётчики причин пересекаются: один профиль может быть занят и одновременно дороже бюджета. Ошибочный ввод → `400` с полями; слишком большой запрос → `413`; недоступный каталог/кеш → `503`. Отсутствие результатов возвращает `200`.

## Проверка основного сценария

| Пример | Что ожидать до выбора тройки |
| --- | --- |
| Алматы, ведущий, корпоратив, 15.10.2026, 1 млн ₸ | 6 подходящих из 10; выдача до 3 |
| Те же условия, 16.10.2026 | 4 подходящих; изменившийся календарь меняет выдачу |
| Алматы, флорист, свадьба, 15.10.2026, 500 тыс. ₸ | 2 подходящих, оба показаны |
| Алматы, ведущий, корпоратив, 15.10.2026, 100 тыс. ₸ | `no_match`, причины видны |
| Астана, декоратор | `category_absent` |

Убедитесь, что занятых нет; повторите запрос и сравните порядок; раскройте источники. Результаты реальных запросов сохранены в `docs/evidence/smoke.json`; скриншоты проверки интерфейса — в той же папке. Это технические свидетельства проверок, не подмена работы приложения.

## Ограничения и дальнейшее развитие

- Каталог — 66 анонимизированных профилей, включая 13 синтетических от организаторов; 18 цен и 8 городов проставлены при подготовке. Это обозначено на карточках.
- Календарь только 23.09–31.12.2026. «Свободен» означает отсутствие занятости **в предоставленном календаре**, не подтверждение подрядчика.
- Цена «от» не гарантирует итоговую стоимость, пожелания не гарантируют наличие услуги; рекламные заявления не проверены независимо.
- Пользовательских исследований, измерений экономии времени и доказанного превосходства над альтернативами пока нет.
- Следующие шаги: подтверждение цен/календарей у подрядчиков, оценка подборок организаторами, сравнение с сортировкой по цене; затем общий кеш, авторизация, ограничение запросов и мониторинг расходов для публичной эксплуатации.
- Удалённое развёртывание не требуется для локальной проверки. Публичный экземпляр нуждается в защите API-бюджета; прототип рассчитан на локальное демо.

## Типичные проблемы

- **Docker daemon недоступен:** запустите Docker Desktop; проверьте `docker info`.
- **Порт 3000 занят:** остановите локальный `npm run dev` либо измените левый порт в Compose, например `3001:3000`.
- **Резервный режим вместо AI:** проверьте ключ, баланс, доступ к обеим моделям и сеть. После исправления используйте новый запрос либо намеренно сбросьте кеш; сохранённые резервные ответы не пересчитываются автоматически.
- **`prepare:data` сообщает 401/403/429:** проверьте ключ/права/лимиты у провайдера. Секреты в логи не выводятся.
- **503 при подборе:** проверьте наличие CSV и права записи в каталог кеша; `docker compose logs --tail=50 app`.
- **Не собирается образ:** проверьте доступ к npm/Docker Hub, повторите `docker compose build`. Для первого запуска нужен интернет.
- **HTML-превью отличается от интерфейса:** HTML из задания — справочный просмотр; источник данных приложения — CSV.
